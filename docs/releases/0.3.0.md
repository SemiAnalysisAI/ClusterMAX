# ClusterMAX 0.3.0

This release adds passive kernel security checks and new audit checks,
and improves audit evidence.
It does not run exploits, change host security settings, or patch a cluster.

## Security checks

- **PwnEscape:** Add a running-kernel check for CVE-2026-99999 across the
  standalone, Slurm, and Kubernetes collectors. The security audit grades
  every worker and control-plane host it can reach. One failing host fails the
  check, and an unread host or a hidden control plane reports
  `coverage-incomplete`, never a pass. Hidden physical hosts and distribution
  backports require provider or vendor evidence.
- **Bad Epoll:** Add CVE-2026-46242 package checks for supported Ubuntu
  generic and NVIDIA kernel families. Keep running-kernel evidence separate
  from newer installed kernels that require a reboot.
- **Evidence handling:** Preserve uncertainty for unreadable livepatch state,
  unsupported firmware trains, incomplete DPU isolation evidence, and failed
  BMC commands.
- **QEMU and VMSCAPE:** Show the QEMU virtio-serial and VMSCAPE verdicts in
  both the CLI and full reports. Hosts without a hypervisor report not
  applicable, and hidden hosts require provider evidence.

## Collection and reporting

- **Kubernetes:** Select Ready, schedulable workers from the primary GPU
  profile. A secondary pool cannot supply facts for that profile.
- **Host software:** Improve loaded NVIDIA driver detection, GPU Operator
  host-root discovery, and CUDA Toolkit evidence from active GPU workloads.
- **Minimum tables:** Reject unusable caches and retain shipped kernel
  mappings when the remote table lacks required release mappings.
- **Slurm workers:** Stream check source to compute workers, so an audit no
  longer needs a shared checkout. NVIDIA-only probes stay on NVIDIA nodes in
  mixed-vendor clusters.

## New audit checks

- **Tenant GPU pods:** Check memlock, shared memory, RDMA, and GDRCopy defaults
  and admission for ordinary and tuned tenant pods. Test pods are created only
  in the full and orchestration profiles.
- **Kubernetes scheduling:** Inventory Kueue, quota, runtime, priority, and
  admission configuration in the tenant namespace. Soft `PreferNoSchedule`
  taints are not reported as placement restrictions.
- **Storage consistency:** Compare mount inventories across all GPU workers.
  An errored mount table is not treated as proof of a missing mount.
- **Huge pages:** Report THP policy and static HugeTLB pools for each node.
  Mixed THP modes do not pass. The allocation trial runs only on explicit
  opt-in.
- **RDMA and fabric evidence:** Preserve configured RDMA resources, failed
  rails, and per-rail firmware, link, and neighbor evidence, including on
  renamed RDMA devices. AMD GPU Operator system pods are supported.
- **Slurm compute workers:** Collect slurmd, CUDA path, geolocation, NHC,
  monitoring placement, and InfiniBand evidence on compute workers.
  SSH failures are reported separately from scheduler rejections.
- **Observability isolation:** Discover query backends and run bounded,
  read-only tenant-isolation checks with TLS verification. Kubernetes audits
  do not probe the operator's own machine.
- **Fleet security minimums:** The focused security audit grades the GPU
  driver, container toolkit, runc, Docker, ConnectX firmware, DCGM, and the
  kernel advisories on every GPU host (up to 32 by default; set
  `CLUSTERMAX_AUDIT_SECURITY_HOST_LIMIT`) and reports the worst host. A host
  the audit cannot read turns a pass into unknown.

## Upgrade notes

- New checks can add warnings to old audit files because those files lack the
  new evidence. Rerun the audit to collect it.
- A passing sampled-worker check does not certify a hidden hypervisor or the
  whole fleet. PwnEscape and the security audit's host-level minimums read
  every reachable GPU host; other checks still sample.
  Provider attestations remain separate evidence.
- Backport and livepatch decisions require evidence for the exact CVE and
  running build. A higher package number alone does not establish a fix.

Install this version with `pip install --upgrade clustermax==0.3.0`.
Use `cmax audit security --show` to inspect the security check inventory.
